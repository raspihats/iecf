# W0018: a pointer that may outlive what it points at, kept only to be compared

Only with `--extension pointers` (in the `codesys` pack). A pointer that
may point into a variable gone when its POU returns - the address of a
VAR_TEMP, of a FUNCTION's or method's variable, of an in-out, or a
pointer given as an input - is refused where it is kept past the call,
[E0027](E0027.md). It is kept, with this warning, in a variable that
only remembers which place it was given: a VAR of the block, PROTECTED
or PRIVATE, that its block, the block declaring it and every block
derived from it only assign whole (`pLast := p`) and compare with `=`
and `<>`, and that no POU names otherwise as a part (`x.pLast`).
Nothing reads through it, indexes it, gives it on or copies it, so
where it points may be gone; iecf's `=` and `<>` of pointers compare
what the pointers hold and never read through them.

```
FUNCTION_BLOCK Info
  VAR pLast : POINTER TO ULINT; path : STRING; END_VAR
  METHOD PUBLIC Get
    VAR_INPUT p : POINTER TO ULINT; END_VAR
    IF pLast <> p THEN
      path := Lookup(p);
      pLast := p;            (* W0018 *)
    END_IF
  END_METHOD
END_FUNCTION_BLOCK
```

TcOpen's `TcoSignalInfo` remembers so which signal it last looked up.
Any other use of the variable - `pLast^`, `pLast[0]`, `q := pLast`,
`F(pLast)`, `<` - brings back the E0027.

The risk: once the variable it pointed into is gone, another variable
may take its place, and a pointer to it compares equal to the one kept.
Here that would keep the path of the signal looked up before. To
silence it, give a pointer to a variable that lives as long as the
program, or keep something that names the place for good.
