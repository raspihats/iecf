# W0014: an expression standing as a statement, its value unused

Only with `--extension expression-statements` (in the `codesys` pack).
Ed.3's statements are assignments, calls, RETURN and the control
statements: an expression on its own, `fb.IsTrue;`, is none, and
without the extension it is [E0005](E0005.md). CODESYS compiles it
with its message C0139, "The code \<code\> has no effect. Is this the
intent?"; TwinCAT runs what it calls. The extension does so:

```
fb.IsTrue;              (* W0014: IsTrue's GET is called, its value unused *)
task.Invoke().Done;     (* W0014: Invoke() and Done's GET are called *)
fb.Status.Text;         (* W0014: no call, nothing is done *)
```

Every call in the expression - a FUNCTION, a method, a block, a
property's GET - is made, in order, as it would be were the value
assigned, and the value is dropped. An expression with no call has no
effect: no code is written for it, as TwinCAT 2's own message says
("No code was generated"), so an index in it is not checked either.
`a = b;` stays [E0005](E0005.md): `=` compares, `:=` assigns.

To mean the same in every tool, assign the value, `dummy :=
fb.IsTrue;`, or call the method on its own.
