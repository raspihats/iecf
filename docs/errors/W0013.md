# W0013: a method using its block's VAR_IN_OUT, bound by the block's last call

Only with `--extension method-in-outs` (in the `codesys` pack). Ed.3
keeps a function block's `VAR_IN_OUT` from its methods (6.6.7.2.3): an
in-out is bound by a call of the block, and a method is called on its
own, with no such binding. CODESYS and TwinCAT let a method use it,
with their compiler warning C0371 ("Access to VAR_IN_OUT ... from
external context"), and the extension does as they do: the method uses
the variable the block's **last call** bound.

```
FUNCTION_BLOCK Axis
  VAR_IN_OUT drive : DriveData; END_VAR
  METHOD PUBLIC Stop
    drive.speed := 0;     (* W0013: the drive the last Axis call gave *)
  END_METHOD
END_FUNCTION_BLOCK
```

A method called before the block was ever called has nothing bound:
a statement using the in-out stops with a NULL fault
(`IECF_FAULT_NULL`) before it runs, as a NULL reference does.
`__ISVALIDREF(drive)` tells whether a call has bound it, and is no
use: `IF __ISVALIDREF(drive) THEN drive.speed := 0; END_IF` is
neither warned nor a fault. Each use is warned, as the same text in a
tool that follows the standard does not compile.

To mean the same in every tool, give the method the variable as its
own `VAR_IN_OUT`.
