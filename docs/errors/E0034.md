# E0034: a structure layout Ed.3 does not allow

A structure type may place its components itself: each one's name is
followed by `AT` and a *relative location*, its byte (and bit) counted
from the start of the structure (Ed.3 6.4.4.7). Gaps are allowed.

```
TYPE
  Com1_data : STRUCT
    head   AT %B0   : INT;          (* bytes 0 and 1 *)
    length AT %B2   : USINT := 26;  (* byte 2 *)
    flag1  AT %X3.0 : BOOL;         (* bit 0 of byte 3 *)
    tail   AT %B25  : BYTE;         (* byte 25: 4 to 24 are a gap *)
  END_STRUCT;
END_TYPE
```

Then:

- **Each component is placed**, or none is: "the name of each
  component of this structure shall be followed by the keyword AT and a
  relative location".

  ```
  Bad : STRUCT
    a AT %B0 : INT;
    b : INT;            (* E0034: b has no place *)
  END_STRUCT;
  ```

- **No two share a bit**, unless the structure is `STRUCT OVERLAP`
  ("The components of the structure shall not overlap in their memory
  layout, except if the keyword OVERLAP has been given"). Two BOOLs at
  two bits of one byte do not overlap.

  ```
  Bad : STRUCT
    w AT %B0 : WORD;    (* bytes 0 and 1 *)
    b AT %B1 : BYTE;    (* E0034: byte 1 is w's *)
  END_STRUCT;
  ```

- **An OVERLAP structure has no initial value given**, neither for a
  component in its type nor for a variable of it ("Overlapped
  structures cannot be initialized explicitly", Ed.3 6.4.4.7.2). Its
  components start at their types' initial values, set in the order
  they are declared: where two share bytes, the later one's are there.

  ```
  Com2_data : STRUCT OVERLAP
    data1 AT %B5 : BYTE;
    data2 AT %B5 : REAL := 1.0;   (* E0034 *)
  END_STRUCT;

  VAR c : Com2_data := (data1 := 3); END_VAR   (* E0034 *)
  ```

- **`STRUCT OVERLAP` places its components.** Without relative
  locations, nothing says which components share which bytes; give each
  one its byte, and those at the same byte share it. Each at `%B0` is
  what CODESYS and TwinCAT call a UNION:

  ```
  U : STRUCT OVERLAP          (* E0034 *)
    r : REAL;
    d : DWORD;
  END_STRUCT;

  U : STRUCT OVERLAP          (* fine: r and d share bytes 0 to 3 *)
    r AT %B0 : REAL;
    d AT %B0 : DWORD;
  END_STRUCT;
  ```

  Their own `UNION ... END_UNION` is not IEC 61131-3; an extension for
  it is proposed in [Extensions](../extensions.md).

What a relative location is written as, and what can be at one, is
[E0022](E0022.md)'s. How such a structure lies in memory, in the
process image and in C, is in docs/c-output.md §4.
