# E0036: an initial value that reads a variable not set up before it

With the extension `initial-expressions`
([Extensions](../extensions.md#initial-expressions-a-variables-initial-value-names-variables-and-calls-functions-as-codesyss-and-twincats-do)),
a variable's initial value may name other variables, worked out as the
variable is set up. The variables are set up in the order they are
declared, so an initial value reads only those declared before it:

```
VAR
    a : INT := 10;
    b : INT := a + 1;        (* fine: a is set up before b *)
    c : INT := d * 2;        (* E0036: d is declared after c *)
    d : INT := 3;
    e : INT := e + 1;        (* E0036: e is set up by this declaration *)
END_VAR
```

An instance - a PROGRAM's, a FUNCTION_BLOCK's or a CLASS's - is set up
once, as the program starts. What it has only while it runs is not
there yet:

```
FUNCTION_BLOCK Fb
VAR_IN_OUT io : INT; END_VAR
VAR_TEMP t : INT; END_VAR
VAR
    x : INT := io;           (* E0036: io is bound only as the block is called *)
    y : INT := t;            (* E0036: t is set up at each run *)
END_VAR
```

A VAR_TEMP's own initial value is worked out at each run, after the
instance is set up: it may name any of the instance's variables, and the
VAR_TEMPs declared before it. A FUNCTION or method is given its inputs,
in-outs and outputs first, then sets up its variables in order, at each
call.

A global's initial value reads the globals declared before it: the
top-level ones are set up first, then a CONFIGURATION's, then each
RESOURCE's.

```
VAR_GLOBAL
    top   : REAL := scale * 100.0;   (* E0036: scale is declared after top *)
    scale : REAL := 1.5;
END_VAR
```

A constant may be named wherever it is declared: the compiler works its
value out. Move the declaration that is read above the one that reads
it.
