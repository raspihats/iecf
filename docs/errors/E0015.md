# E0015: an assignment to what cannot be assigned

The left of `:=`, the target of `=>`, an in-out argument and a FOR
loop's variable must be variables that the POU may write: not a
`CONSTANT`, not a literal or a call, not a function block's output
from outside the block, not an input address.

```
VAR CONSTANT LIMIT : INT := 10; END_VAR
VAR t : TON; END_VAR
LIMIT := 5;        (* E0015: a CONSTANT *)
t.Q := TRUE;       (* E0015: only TON writes its Q *)
```

A FOR loop's statements do not change its control variable, nor its
initial or final value: they "shall not be altered by any of the
repeated statements" (Ed.3 7.3.3.4.2).

```
FOR i := 1 TO n DO
    i := i + 1;    (* E0015: the control variable *)
    n := 0;        (* E0015: what the final value reads *)
END_FOR;
```

What the values read through their operators and indices is checked,
`n`, `a[2]`, `s.n`, and whatever holds it, `s`: a statement assigning
it with `:=`, `?=` or `REF=`, as a call's output `=>`, or as an inner
FOR's variable. A call's arguments are its own (`TO UPPER_BOUND(v, 1)`
lets the loop set `v[i]`), and what changes through an in-out, a
reference or another POU is not seen; the loop still ends when its
variable leaves the TO range ([Statements](../behaviour/statements.md#for)).
