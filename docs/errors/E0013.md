# E0013: a value whose type does not convert implicitly

A value converts to another type implicitly only where no value or
precision can be lost (Ed.3 6.6.1.6 and Figure 11): `INT` to `DINT` or
`REAL`, `BYTE` to `WORD`, `TIME` to `LTIME`. Anything else takes a
conversion function, which the message names when there is one.

```
VAR i : INT; d : DINT; r : REAL; END_VAR
d := i;              (* fine: INT widens to DINT *)
i := d;              (* E0013: use DINT_TO_INT *)
r := d;              (* E0013: use DINT_TO_REAL; a DINT can lose digits in a REAL *)
```

Ed.2 had no implicit conversions; matiec, which follows Ed.2, refuses
`d := i` too.

With `--extension bit-string-arithmetic`, a bit string goes where its
unsigned integer would (`i := b` for an INT and a BYTE), and BYTE and
WORD convert to and from REAL and LREAL by value
([extensions](../extensions.md#bit-string-arithmetic-arithmetic-on-byte-word-dword-and-lword-each-counted-as-the-unsigned-integer-of-its-width)).
DWORD_TO_REAL stays Ed.3's binary transfer either way.

With `--extension implicit-narrowing`, an integer or bit string goes
where another is wanted, converted as its `*_TO_*` would, and is warned
([W0010](W0010.md)) instead.

A date, time of day or date and time to or from a number
(`DT_TO_DWORD`, `UDINT_TO_DATE`) is E0013 too: Figure 11 has none.
`--extension date-number-conversions` takes them, in seconds since 1970
and milliseconds since midnight, as CODESYS and TwinCAT count
([extensions](../extensions.md#date-number-conversions-date-tod-dt-to-and-from-numbers-seconds-since-1970-milliseconds-since-midnight)).
