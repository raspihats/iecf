# W0006: a reference a RETAIN program instance keeps

A program instance declared RETAIN in the CONFIGURATION keeps, across a
warm restart, the variables of its PROGRAM's sections that say neither
RETAIN nor NON_RETAIN (Ed.3 6.5.6.2). A reference (`REF_TO`) among
them is kept as it is: it holds where a variable was, and is valid
after the restart only if that variable is still there - it is when
the same program restarts in place, it may not be after a new build or
on another memory layout. CODESYS and TwinCAT leave a pointer in
retained memory to the programmer the same way ("the address values
may change"); iecf compiles it and warns (docs/dependencies.md).

```
PROGRAM main
VAR r : REF_TO INT; level : INT; END_VAR     (* r is kept with p *)
END_PROGRAM
CONFIGURATION c
  RESOURCE cpu ON PLC
    TASK t(INTERVAL := T#10ms, PRIORITY := 1);
    PROGRAM RETAIN p WITH t : main;          (* W0006 *)
  END_RESOURCE
END_CONFIGURATION
```

Declare it `VAR NON_RETAIN r : REF_TO INT; END_VAR` to have it set
again at every start, and take the reference anew. A variable of an
INTERFACE in such a section is warned of too, and is not kept: it is
set to its initial value at every start, as it holds the address of
code. A reference in a section that is itself RETAIN stays an error
([E0027](E0027.md)).
