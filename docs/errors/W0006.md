# W0006: a reference kept across a warm restart

A reference (`REF_TO`, or `REFERENCE TO` with the reference-to
extension) in a RETAIN section, or in a structure, array or function
block instance there, is kept as it is across a warm restart. So is one
in a section that says neither RETAIN nor NON_RETAIN of a program
instance declared RETAIN in the CONFIGURATION (Ed.3 6.5.6.2).

A reference holds where a variable was. It is valid after the restart
only if that variable is still there: it is when the same program
restarts in place, it may not be after a new build or on another
memory layout, and using it then is as using any stale address.
CODESYS and TwinCAT leave a pointer in retained memory to the
programmer the same way (Beckhoff: "Avoid using the POINTER TO data
type in persistent variable lists, since the address values may
change"); iecf compiles it and warns (docs/dependencies.md).

```
VAR RETAIN
    r : REF_TO INT;      (* W0006 *)
    level : INT;         (* retain the value; REF(level) again at start *)
END_VAR
```

```
PROGRAM main
VAR r : REF_TO INT; level : INT; END_VAR     (* r is kept with p *)
END_PROGRAM
CONFIGURATION c
  RESOURCE cpu ON PLC
    TASK t(INTERVAL := T#10ms, PRIORITY := 1);
    PROGRAM RETAIN p WITH t : main;          (* W0006 *)
  END_RESOURCE
END_CONFIGURATION
```

Declare it in a section that is not RETAIN (`VAR NON_RETAIN` in a
PROGRAM whose instance is RETAIN) to have it set again at every start,
and take the reference anew.

A variable of an INTERFACE is not kept. In a RETAIN section it is an
error ([E0027](E0027.md)); in a RETAIN program instance it is warned
of with this code and set to its initial value at every start.
