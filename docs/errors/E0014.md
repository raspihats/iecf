# E0014: operands an operator or index does not take

Arithmetic takes numbers (ANY_NUM), `MOD` integers, `AND`, `OR`, `XOR`
and `NOT` booleans or bit strings (ANY_BIT), and both sides of an
operator must meet in one type by implicit conversion (Ed.3 6.6.2.5).
An array index is an integer; `x.3` takes a bit string, and a variable
(Ed.3 6.6.1.3): `F(1).3`, a part of a call's result, is stored in a
variable first; `r^` takes a reference. A comparison takes elementary values (Ed.3 Table 33,
ANY_ELEMENTARY): two arrays, two structures or two function block
instances are not compared, their elements, fields or variables are.

```
VAR b : BOOL; i : INT; d : DINT; r : REAL; END_VAR
i := i + b;        (* E0014: INT and BOOL *)
r := r + d;        (* E0014: DINT does not widen to REAL; DINT_TO_REAL *)
i := i AND 1;      (* E0014: AND takes BOOL or bit strings, not INT *)
```

Arithmetic on a bit string (`DWORD + 1`, `BYTE * 2`), and a bit string
as an array index, are CODESYS's and TwinCAT's; the message names
`--extension bit-string-arithmetic`, which counts a bit string as the
unsigned integer of its width
([extensions](../extensions.md#bit-string-arithmetic-arithmetic-on-byte-word-dword-and-lword-each-counted-as-the-unsigned-integer-of-its-width)).

So are a shift of an integer or by a bit string's count, a part of an
integer (`i.3`) and EXPT of an integer base: CODESYS's and TwinCAT's,
each named in its message - `--extension integer-shifts`,
`integer-bit-access`, `integer-expt` ([extensions](../extensions.md)).

A pointer (the pointers extension) takes `+` and `-` of an integer, `-`
of another pointer, and the comparisons: `p + 1.5` or `p * 2` is E0014
([Pointers](../behaviour/pointers.md)).

`DATE + TIME`, which Table 35 has not, is E0014 unless `--extension
date-time-arithmetic` names it, a TIME of whole days
([extensions](../extensions.md#date-time-arithmetic-date--time-and-date---time-the-time-a-whole-number-of-days)).
