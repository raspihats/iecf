# E0027: a reference where it cannot be

A reference (`REF_TO`, or `REFERENCE TO` with the reference-to
extension) holds where a variable is, which means something only inside
the running program:

- **VAR_IN_OUT**: "References shall not be used as in-out variables"
  (Ed.3 6.4.4.10.3). Pass it as an input: the reference is copied, what
  it references is shared;
- **RETAIN**, for a variable of an INTERFACE, or a structure, array or
  function block instance that holds one: an interface is a reference
  to an instance (Ed.3 6.6.6.5.1) and holds the address of its code,
  which a restart after a new build would leave pointing nowhere. A
  retained `REF_TO` is compiled and warned of instead
  ([W0006](W0006.md)), as is one a RETAIN program instance keeps;
- **at an address** (`AT %MB0`): the process image holds values the host
  and other devices read, and a reference is no value to them;
- **REFERENCE TO** ([extensions](../extensions.md), reference-to): not
  an array of them, not a `REF_TO` one, and not a REFERENCE TO a
  reference, as in CODESYS and TwinCAT. Use `REF_TO` for those.

```
VAR RETAIN
    door : IDoor;        (* E0027: IDoor is an INTERFACE *)
END_VAR
```

Under `--extension pointers`: a pointer that may point into a variable
gone when its POU returns - `ADR` of a FUNCTION's or method's variable,
of a VAR_TEMP, of an in-out, or a pointer held in such a variable or
given as an input - stored where it outlives the call (a static
variable, a block's input, a global, an in-out, an output, a
FUNCTION's result) is E0027; so is `POINTER TO` anything but data (a
block, a reference, an interface, a pointer)
([Pointers](../behaviour/pointers.md#where-a-pointer-may-be-kept)).

Under `--extension dynamic-memory`: in a project that calls `__NEW`, a
RETAIN variable that holds a pointer is E0027, not W0006 - it may hold
a block of a task's pool, which every start empties; declare it VAR
NON_RETAIN. `__NEW` of a function block, a class or an interface is
E0027 too: a pointer points to data
([dynamic-memory](../extensions.md#dynamic-memory-codesyss-__new-and-__delete-memory-taken-while-the-program-runs-from-its-tasks-pool-each-pointer-to-it-checked)).

Under `--extension method-in-outs`: a call of a function block binding
its VAR_IN_OUT, one some method of the block uses after the call, to a
variable that may be gone by then - a VAR_TEMP, a FUNCTION's or
method's variable, an in-out of the caller's own - is E0027: give one
that lives as long as the instance
([extensions](../extensions.md#method-in-outs-a-method-reaches-its-blocks-var_in_out-as-codesys-lets-it-with-a-warning-warned)).

Under `--extension query-pointer` a `POINTER TO` a function block or
a class is no E0027: it is a reference to an instance
([query-pointer](../extensions.md#query-pointer-codesyss-__querypointera-p-the-instance-an-interface-refers-to-as-a-pointer-to-its-block-its-type-checked)).
