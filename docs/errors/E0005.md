# E0005: the text does not fit the grammar here

The message says what was expected and what was found. iecf then skips
to the end of the statement, declaration or block it was reading and
carries on, so one mistake gives one error, and the rest of the file is
still checked.

```
IF x > 0
    y := 1;        (* E0005: expected THEN *)
END_IF;
```

Every statement ends with `;`, including `END_IF`, `END_CASE`,
`END_FOR`, `END_WHILE` and `END_REPEAT` (Ed.3 Annex A, `Stmt_List`);
`--extension optional-semicolons` lets those five go without it, as
CODESYS and TwinCAT do
([extensions](../extensions.md#optional-semicolons-no--after-end_if-end_case-and-the-other-ends-as-codesys-and-twincat-take-it)). A
CASE has at least one list of values before its ELSE or END_CASE
(`Case_Selection +`).

A section takes the qualifiers its grammar and Ed.3 6.5.6.2 give it,
one at most: CONSTANT on VAR, VAR_EXTERNAL and VAR_GLOBAL; RETAIN and
NON_RETAIN on a static VAR (not a FUNCTION's or a METHOD's),
VAR_INPUT, VAR_OUTPUT and VAR_GLOBAL, "but not in VAR_IN_OUT section".
`VAR_IN_OUT CONSTANT`, CODESYS's, is E0005 too unless `--extension
in-out-constant` names it ([extensions](../extensions.md#in-out-constant-codesyss-var_in_out-constant-given-any-value-a-string-of-any-length)),
and so is CODESYS's `VAR_INPUT CONSTANT` unless `--extension
input-constant` does, which reads it as a plain VAR_INPUT
([extensions](../extensions.md#input-constant-codesyss-var_input-constant-a-plain-var_input-outside-its-cfc-editor)).

```
VAR_INPUT CONSTANT k : INT; END_VAR        (* E0005: CONSTANT is for VAR, VAR_EXTERNAL, VAR_GLOBAL *)
VAR_TEMP RETAIN n : INT; END_VAR           (* E0005: a VAR_TEMP lives only in its call *)
VAR CONSTANT RETAIN m : INT := 1; END_VAR  (* E0005: one qualifier *)
```

Without an extension that names them, E0005 too: a STRING's length in
parentheses, `STRING(20)` (Ed.3 writes `STRING[20]`; `--extension
string-parentheses`), and a function block or class instance in
VAR_TEMP, or in a FUNCTION's or a METHOD's VAR, which Ed.3 6.6.3.2 rule
17 keeps out of the VAR_TEMP section and 6.5.2.2 makes a VAR_TEMP
there (`--extension temp-instances`).

An assignment is a statement, not a value (Ed.3 7.3.2, Table 72):
`a := b := 0;` is E0005 unless `--extension chained-assignment` reads it
as `b := 0; a := b;`
([extensions](../extensions.md#chained-assignment-a--b--0-assigned-right-to-left-as-codesys-twincat-and-siemens-chain-them));
with it, an inner target with a call in it, `a := arr[f()] := 1`, is
E0005 still, as reading it back would call again.

Arguments where an instance is declared, `fb : T(THIS^)`, CODESYS's
FB_init, are E0005 unless `--extension fb-init` takes them
([extensions](../extensions.md#fb-init-codesyss-fb_init-given-arguments-where-an-instance-is-declared-called-as-it-is-set-up)).

`PROPERTY`, CODESYS's and TwinCAT's, is E0005 unless `--extension
properties` takes it
([extensions](../extensions.md#properties-codesyss-property-a-get-and-a-set-called-where-it-is-read-and-assigned)).

`JMP name;` and `name:` are Instruction List's (Ed.3 7.2), not
Structured Text's: E0005 in ST unless `--extension jump-labels` names
them
([extensions](../extensions.md#jump-labels-jmp-and-labels-in-st-as-codesys-and-twincat-write-them-never-into-a-loop-or-branch)).

Ways of writing CODESYS takes and Ed.3's grammar does not are E0005
unless their extension is named: `END_STRUCT` with no `;` after it
(`--extension struct-semicolon`), a real literal with an exponent and no
point, `1E37` for `1.0E37` (`--extension real-without-point`), and an
array's initial values without their brackets, `:= 1, 2, 3` for `:= [1,
2, 3]` (`--extension bare-array-init`); see
[extensions](../extensions.md). `FUNCTIONBLOCK`, written as one word in
CODESYS 2.3 exports, is E0005 whatever is named - CODESYS 3 refuses it
too (its error C0098) - and the block is then read as the
FUNCTION_BLOCK meant, so it is the only error.

```
TYPE P : STRUCT a : INT; END_STRUCT END_TYPE   (* E0005: END_STRUCT; *)
OUT_MIN : REAL := -1E37;                       (* E0005: -1.0E37 *)
days : ARRAY[1..3] OF INT := 0, 31, 59;        (* E0005: [0, 31, 59] *)
FUNCTIONBLOCK fb                               (* E0005: FUNCTION_BLOCK *)
```

A keyword is not a name (Ed.3 6.1.3): `step : INT;` is E0005, said
once per name and file. CODESYS does not reserve STEP, ON, R_EDGE and
F_EDGE; `--extension keyword-names` takes those four as names wherever
their keyword cannot stand ([extensions](../extensions.md#keyword-names-step-on-r_edge-and-f_edge-as-names-which-codesys-does-not-reserve)).

A name has an underscore only singly and not at its end: `__LIM_SW5`,
`LIM__SW5` and `LIM_SW5_` "are not valid identifiers" (Ed.3 6.1.2,
whose examples these are). One underscore may start a name, `_LIM`.

A section or a body where the grammar of its POU has none is E0005 too:
VAR_GLOBAL in a FUNCTION_BLOCK, a FUNCTION or a METHOD (a
CONFIGURATION, a RESOURCE or a PROGRAM declares one, Ed.3 6.5.2.2; the
others reach it by VAR_EXTERNAL), and SFC in a FUNCTION or a METHOD,
which keeps no state for the steps (Ed.3 6.7.1).

An SFC action's time, `act(D, t)`, is a duration literal or a variable
(Ed.3 Annex A, Action_Time): an expression there is E0005. Assign it to
a TIME variable and name that. So are, in an SFC: a qualifier Table 59
does not have, a timed one (L, D, SD, DS, SL) without its time, a
transition's PRIORITY that is not an unsigned integer literal, and
statements beside the chart - a body is in one language (FB_Body), and
an ACTION is a part of an SFC.

```
INITIAL_STEP s0: Fill(L); END_STEP          (* E0005: L takes a time: Fill(L, T#5s) *)
TRANSITION (PRIORITY := k) FROM s0 TO s1    (* E0005: PRIORITY := 2 *)
```

CODESYS's `POINTER TO T` is E0005 unless `--extension pointers` names
it ([Pointers](../behaviour/pointers.md)).
