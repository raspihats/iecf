# W0020: a structure with `*` components in a block's input or a method's variable

Only with `--extension auto-addresses`. A structure type whose
components are at `*` addresses, `q AT %Q* : INT`, is completed per
instance by VAR_CONFIG, and Ed.3 says: "Variables of this type shall
not be used in a VAR_INPUT, VAR_IN_OUT, or VAR_TEMP section" (6.4.4.8);
iecf refuses one there, [E0022](E0022.md). TwinCAT compiles two of
them, and with the extension iecf does too, with this warning:

- **a FUNCTION_BLOCK's or CLASS's `VAR_INPUT`**: its components are
  placed per instance, as a VAR's - where VAR_CONFIG says, or by iecf
  ([W0015](W0015.md)). A call giving the input a value writes the
  components where they are placed; one in `%I` is overwritten by the
  next inputs read, before the next cycle.
- **a FUNCTION's or method's `VAR`**: its components are plain memory of
  the call, each at no address; the variable holds a copy, linked to
  nothing.

```
TYPE Io : STRUCT count AT %I* : UINT; END_STRUCT; END_TYPE
FUNCTION_BLOCK Master
  VAR_INPUT Inputs : Io; END_VAR          (* W0020: placed per instance *)
  METHOD Check
    VAR copy : Io; END_VAR                (* W0020: plain memory *)
    copy := Inputs;
  END_METHOD
END_FUNCTION_BLOCK
```

TcOpen's `TcoEthercatMasterDevice` is written so, with the types
TwinCAT generates from its I/O configuration. A program's input, a
VAR_TEMP and an array of such a type stay E0022. To silence it, keep
the structure in a block's VAR or VAR_OUTPUT, or take it as a
VAR_IN_OUT.
