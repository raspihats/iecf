# E0035: a VAR_ACCESS entry that does not fit the variable it names

`VAR_ACCESS` gives a variable a name under which a communication
service reaches it (Ed.3 6.8.1; IEC 61131-5): `name : path : type
direction;`, in a CONFIGURATION, or in a PROGRAM for its own variables
(Table 47, feature 9).

The path leads to a variable: a global of the configuration or of a
resource (`R.g`), a directly represented variable (`%IX1.0`, `R.%QW2`),
or an input, output or internal variable of a program instance or of a
function block instance in one (`R.P.fb.x`), a field, an element or a
part of one. It does not lead to a VAR_TEMP, a VAR_EXTERNAL or a
VAR_IN_OUT ("It shall not be possible to define access paths to
variables that are declared in VAR_TEMP, VAR_EXTERNAL or VAR_IN_OUT
declarations"), nor stop at a resource or a program instance.

The direction is READ_ONLY when none is written; a CONSTANT is
READ_ONLY. The type is the variable's own (a different one is
[E0013](E0013.md)).

```
PROGRAM main
VAR CONSTANT limit : INT := 5; END_VAR
VAR_TEMP t : INT; END_VAR
END_PROGRAM
CONFIGURATION c
  RESOURCE r ON PLC
    TASK fast(INTERVAL := T#10ms, PRIORITY := 1);
    PROGRAM p WITH fast : main;
  END_RESOURCE
  VAR_ACCESS
    A : r.p.t     : INT;                (* E0035: a VAR_TEMP *)
    B : r.p.limit : INT READ_WRITE;     (* E0035: a CONSTANT is READ_ONLY *)
    C : r.p       : INT;                (* E0035: a program instance, no variable *)
  END_VAR
END_CONFIGURATION
```

What iecf makes of an entry is a row of the access table beside the
symbol table (docs/c-output.md §6): the name, the variable's path and
the direction, for the platform's communication to use.
