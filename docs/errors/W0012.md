# W0012: a function block's internal variable read from outside

Only with `--extension internal-reads` (in the `codesys` pack). Ed.3
lets a function block's inputs and outputs be reached from outside an
instance, `t.Q`, `t.IN`, and nothing else: its `VAR` is its own
(6.5.2.2). CODESYS and TwinCAT also let a `VAR` variable be **read**
through the instance, never written, and the extension does as they
do; each read is warned, as CODESYS's own static analysis flags it
(rule SA0102: "contradicts the principle of data encapsulation").

```
FUNCTION_BLOCK Acc
  VAR_INPUT x : INT; END_VAR
  VAR count : INT; END_VAR
  count := count + 1;
END_FUNCTION_BLOCK

n := a.count;      (* W0012: read, as CODESYS lets it be *)
a.count := 0;      (* E0010 still: never written from outside *)
```

Only a plain `VAR` of a FUNCTION_BLOCK, its own or a base's: not a
`VAR_TEMP` (it lives only in a call), not a `VAR_EXTERNAL`, not a CLASS's
(whose `VAR PUBLIC` says what is seen), not one declared with an access
specifier (that specifier rules, E0030). Read means read: not the target
of an assignment, nor of `=>`, nor a part of one. A method of an
internal instance is called through it, `a.inner.m()`, the instance
read to call it (warned too); its body, `a.inner()`, is not.

To mean the same in every tool, declare what is read outside as a
`VAR_OUTPUT`.
