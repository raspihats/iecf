# W0017: a pointer converted to a number, ULINT or LWORD, that names the place it points at

Only with `--extension pointers` (in the `codesys` pack). Ed.3 has no
pointers; CODESYS's and TwinCAT's are addresses, and their ADR "delivers
the address of its argument in a PVOID or, depending on the runtime
system, in a DWORD (32-bit systems) or LWORD (32 and 64-bit systems)"
([Beckhoff ADR](https://infosys.beckhoff.com/content/1033/tc3_plc_intro/2529015179.html)).
iecf's pointers are checked, and no number is an address: a number
never converts to a pointer ([E0013](E0013.md)). A pointer converts to
a ULINT or an LWORD, one way only, and this warning says where: the
number names the place it points at - in C memory its address, in the
process image its area and byte - and is 0 for NULL. Two pointers to
one place give one number, to two places two, so it serves as an
identity, as TcOpen's `_Identity := ADR(THIS^)` compares instances.
Under query-pointer, `ADR` of an instance converts the same.

```
VAR p : POINTER TO INT; x : INT; id : ULINT; END_VAR
p := ADR(x);
id := p;              (* W0017: a number naming x *)
id := ADR(x);         (* W0017: the same number *)
```

The number is the platform's: it differs from build to build and from
run to run, so it is not one to keep across a restart, to compute
with, or to send away. To silence it, compare the pointers themselves,
`p = q`.
