# W0010: a number converted implicitly to a type that may not hold it

Only with `--extension implicit-narrowing`. Ed.3 converts implicitly
only where every value of the source is one of the target (Figure 11's
"i": INT to DINT, BYTE to WORD); anything else takes a conversion
function, and without the extension is [E0013](E0013.md). CODESYS and
TwinCAT convert the rest too, and warn (CODESYS C0195, C0196, C0197:
"possible loss of information"). With the extension, iecf does the
same between integers and bit strings, from an integer to a real, and
from LREAL to REAL: the value goes where it is
wanted - an assignment, an argument, a result, an initial value -
converted as the explicit `*_TO_*` would, and this warning says where.

```
VAR i : INT; d : DINT := 100000; w : WORD; u : UINT; END_VAR
i := d;          (* W0010: DINT to INT, as DINT_TO_INT: -31072, flagged *)
w := i;          (* W0010: INT to WORD, as INT_TO_WORD: its bits *)
u := i;          (* W0010: INT to UINT: a negative i flagged *)
```

What the value becomes is the explicit conversion's
([Conversions](../behaviour/conversions.md)): between integers, one the
target holds is kept and one it does not keeps its low bits and is
flagged (`IECF_FAULT_CONVERSION`); to or from a bit string, the bits
move, the low ones kept, unflagged; into a real, rounded to the
nearest it holds, an LREAL beyond REAL's range infinite and flagged.
Not covered: a real to an integer, BOOL, durations and dates, which
keep Figure 11's rules.

To silence it, write the conversion: `i := DINT_TO_INT(d);` says the
same, in every tool.
