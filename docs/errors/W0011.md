# W0011: DWORD_TO_REAL or its kin converted by value, not by Ed.3's binary transfer

Only with `--extension codesys-real-conversions` (in the `codesys`
pack). Ed.3 defines `DWORD_TO_REAL`, `REAL_TO_DWORD`, `LWORD_TO_LREAL`
and `LREAL_TO_LWORD` as binary transfers: the IEEE 754 bits move
(Table 25, Figure 11), and without the extension iecf does that. CODESYS
and TwinCAT convert them by value instead, and the extension does as
they do - the DWORD counted as a UDINT, the LWORD as a ULINT. Each use
is warned, as the same text means another number in a tool that follows
the standard.

```
r := DWORD_TO_REAL(DWORD#100);   (* W0011: 100.0 here; Ed.3's bits give 1.4E-43 *)
d := REAL_TO_DWORD(2.5);         (* W0011: 2, half to even; Ed.3's bits give 16#40200000 *)
```

To mean the same in every tool, write the conversion through the
unsigned integer: `UDINT_TO_REAL(DWORD_TO_UDINT(d))`,
`UDINT_TO_DWORD(REAL_TO_UDINT(r))`; for the bits, write nothing that
needs this extension
([extensions](../extensions.md#codesys-real-conversions-dword_to_real-and-its-kin-by-value-as-codesys-converts-them)).
