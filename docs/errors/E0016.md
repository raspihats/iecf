# E0016: a call that does not fit what it calls

A function or a function block is called with its arguments either
all by name or all in order (Ed.3 6.6.1.4, 6.6.3.4.1) - in order,
every input, output and in-out, as declared and none left off, EN and
ENO apart ("exactly the same number of parameters, in exactly the same
order", 6.6.1.4.2); a program's
connections are by name; a function block is called through an
instance, not by its type name; `:=` passes an input or in-out, `=>` takes an
output; every name must be one of the callee's parameters. Every
in-out is given a variable (Ed.3 6.6.1.4 rule 2, "of any call"): at
each call of a function and of a function block - a block does not
keep the variable an earlier call gave it - and in a resource's
connections for a program, which bind it to a global.

```
VAR t : TON; END_VAR
TON(IN := x, PT := T#1s);     (* E0016: call an instance: t(...) *)
t(IN := x, Q := y);           (* E0016: Q is an output: Q => y *)
t(x, T#1s);                   (* E0016: in order, TON takes IN, PT, Q, ET *)
t(x, T#1s, done, elapsed);    (* fine *)
acc(n := total, a := 1);
acc(a := 2);                  (* E0016: acc's VAR_IN_OUT n is not passed *)
PROGRAM p WITH fast : counter;  (* E0016: counter's VAR_IN_OUT n is not
                                   connected: counter(n := g) *)
```

A FUNCTION, function block, PROGRAM or method that can call itself -
directly, or through others - is refused: recursion, which Ed.3 6.6.1
leaves to the implementer, iecf does not allow, its stack having no
bound. A call through an instance, THIS, an in-out or an interface
counts as calling every override or implementation that could run
there. The message names the cycle; [Implementer
extensions](../extensions.md) describes a proposed opt-in.

```
FUNCTION Ping : INT
    VAR_INPUT n : INT; END_VAR
    Ping := Pong(n - 1);       (* E0016: PING -> PONG -> PING *)
END_FUNCTION
FUNCTION Pong : INT
    VAR_INPUT n : INT; END_VAR
    Pong := Ping(n - 1);
END_FUNCTION
```

Rewrite it as a loop. Inside a FUNCTION, its own name is its result:
`Fact(n - 1)` there is a call of a number, also E0016.

A standard function called by name may leave inputs out, each then its
type's default (Ed.3 6.6.1.4.2): `LIMIT(IN := x, MX := 5)` has MN 0.
A generic one needs an input to take its type from, and an extensible
one has as many inputs as the highest name given (6.6.2.5.1), at least
as many as it takes in order, at most 1024
([Implementer choices](../dependencies.md#a-standard-functions-inputs-left-out-ed3-66142-66251)):

```
i := LIMIT(IN := x, MX := 5);  (* fine: MN is 0 *)
i := ADD(IN3 := x);            (* fine: 0 + 0 + x *)
i := ABS();                    (* E0016: ABS takes its type from IN *)
i := MUL(IN1 := x);            (* E0016: one input; MUL takes IN1 to IN2 *)
```

A program's connection names what Ed.3 6.8.2's grammar lets it
(Prog_Data_Source, Data_Sink, Global_Var_Access): an input a constant,
an enumerated value, a global variable or one field of one, or an
address; an output a global variable, one field of one, or an address.
An array's element, an expression or a field of a field is none of
them:

```
PROGRAM p WITH fast : counter(
    n := g,                     (* fine *)
    step := gp.x,               (* fine: one field of a global *)
    limit := ga[2],             (* E0016: an element *)
    start := g + 1);            (* E0016: an expression *)
```
