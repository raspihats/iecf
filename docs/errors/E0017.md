# E0017: a VAR_EXTERNAL that matches no VAR_GLOBAL

`VAR_EXTERNAL` names a global variable declared in a `VAR_GLOBAL`
block of the configuration, a resource, or a global variable list, with
the same type (Ed.3 6.5.2.2). A global declared `CONSTANT` must be
`VAR_EXTERNAL CONSTANT` where it is used (Ed.2 Table E.1).

```
VAR_GLOBAL counter : INT; END_VAR
PROGRAM p
VAR_EXTERNAL count : INT; END_VAR    (* E0017: no global named count *)
END_PROGRAM
```

Which global it is depends on where the POU runs: each CONFIGURATION
has its own, each RESOURCE in it, and each instance of a PROGRAM that
declares a VAR_GLOBAL, so a POU two of them run is checked in each, and the message names the one that lacks it. A POU no
configuration runs - a library's - is checked against every global of
the name.

```
CONFIGURATION a
  VAR_GLOBAL count : INT; END_VAR
  RESOURCE r ON PLC TASK t(INTERVAL := T#10ms, PRIORITY := 1); PROGRAM p1 WITH t : p; END_RESOURCE
END_CONFIGURATION
CONFIGURATION b                      (* E0017 at p's count: none in b *)
  RESOURCE r ON PLC TASK t(INTERVAL := T#10ms, PRIORITY := 1); PROGRAM p1 WITH t : p; END_RESOURCE
END_CONFIGURATION
```

Two resources may each declare a global of one name, and a
FUNCTION_BLOCK or PROGRAM run in both reaches its own resource's. A
FUNCTION cannot: it has no instance to hold which one, so the global
it names is the same wherever it runs (docs/dependencies.md).

```
FUNCTION f : INT
VAR_EXTERNAL g : INT; END_VAR        (* E0017: r1's g or r2's? *)
f := g;
END_FUNCTION
PROGRAM p
VAR x : INT; END_VAR
x := f();
END_PROGRAM
CONFIGURATION c
  RESOURCE r1 ON PLC
    VAR_GLOBAL g : INT; END_VAR
    TASK t(INTERVAL := T#10ms, PRIORITY := 1); PROGRAM p1 WITH t : p;
  END_RESOURCE
  RESOURCE r2 ON PLC
    VAR_GLOBAL g : INT; END_VAR
    TASK t(INTERVAL := T#10ms, PRIORITY := 1); PROGRAM p1 WITH t : p;
  END_RESOURCE
END_CONFIGURATION
```
